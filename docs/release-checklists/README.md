# Release checklists

One file per "big update" release (see `docs/RELEASE_TESTING_PLAN.md` §6 for
what counts as a big update).

**How to use:**

1. Copy `TEMPLATE.md` to `YYYY-MM-DD-<short-name>.md` (e.g.
   `2026-05-12-evidence-scoring-rework.md`).
2. Fill it in as you work through the release.
3. Commit it alongside the release tag / merge commit. The checked-in file is
   the audit trail.

Standard (non-big) updates do not need a checklist file — just the §3
mandatory automated checks from the plan.
